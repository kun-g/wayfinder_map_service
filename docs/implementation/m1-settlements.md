# M1 Settlement and explicit reopening slice

Implements [Settlement/reopen](https://github.com/kun-g/wayfinder_map_service/issues/6) against the accepted [M1 handoff](../spec/m1.md), following [Claims](m1-claims.md). Verification commands: `npm run typecheck`, `npm test` and `git diff --check`. The [cumulative acceptance matrix](m1-acceptance.md) maps all 56 scenario groups to executable assertions across the six implementation slices; neither document substitutes for those assertions or Issue/PR closure.

## Public behavior

The Command union adds a correlated SettleCommand and `ticket.reopen`. Grilling/prototype settle with Decision (statement/rationale), research with Finding (statement, optional string limitations), and task with Completion (statement, optional plain-record JSON resultingFacts). Required text is nonblank but never implicitly trimmed. Resulting facts accept arbitrary keys, unlike namespaced Extensions. Runtime input validation checks every command before execution or stale-head comparison, including nested data descriptors, plain object/array shapes, finite acyclic JSON and unknown fields.

Settlement requires Evidence[], Reference[], semantic Provenance and Extensions. Each Evidence has its own Extensions and at least one Reference or explicit Provenance. Finding requires at least one Evidence or Reference; sourced inconclusive findings and empty limitations are valid. Opaque locators are retained without fetching. Mutation author/time, introducedAtRevision, status, IDs and transcripts cannot be installed through Settlement/outcome/Evidence/Reference/Provenance input. No new public validator or import port is introduced.

Settlement checks command-position existence, open lifecycle, current matching Claim, all settled prerequisites and actual TicketType matching the command's type. Missing Claim returns `claim_required`, wrong session `claim_mismatch`, open prerequisite `unsettled_dependency`, and a valid but different command type `settlement_type_mismatch`. Successful settlement retains descriptions/Dependencies, atomically installs one stored typed Settlement, clears Claim and derives introduction context from the proposed next Revision. Revision actor/client may differ from the claimant. Unrelated edits preserve original introduction context.

Settled Tickets are wholly immutable except explicit reopening. Reopen requires a settled target and exact nonblank reason; open targets return `ticket_not_settled`. It retains descriptions/Dependencies and leaves open/unclaimed with no current Settlement. The removed result remains in immutable historical snapshots. Reopening upstream cannot silently reopen settled descendants, clear downstream Claims or remove edges. Every affected settled descendant must be explicitly reopened; a blocked claimed dependent must explicitly release/clear in the batch. Upstream-first ordering is valid because graph checks inspect the final state. Conversely, a failed command-position acquire/settle cannot be rescued by later commands.

Reopening and re-settling the same result gets a new introduction number and author context, including in one batch. Acquire/settle/reopen returning the original unclaimed state with no net business change is `no_changes`. Ordered semantic summaries retain reopen/clear reasons and command positions; full-state history, not replay, remains authoritative. Historical result/Claim reads never restore either or move current head/Frontier.

The real memory Adapter retains its same three asynchronous operations. Settlement/reopen reuse atomic publication, authoritative head comparisons, exact operation-specific commit results, immutable history, pre-publication failure behavior and captured/detached nested values. Same-head result writers cannot both publish. Mutation of original/prepared/current/read/commit Settlement, Evidence, Provenance, References, resultingFacts and author values cannot change storage. Supplemental trusted-envelope tests verify nested capture without creating an ordinary caller constructor.

## Slice traceability

`tests/settlements.test.ts` covers all four result types, focused actual-type/outcome errors, minimal/sourced result variants, every new command-stage code and submitted position, full raw/typed nested validation paths, reopen/re-settlement introduction records, settled immutability, complete transitive downstream reopening, both release/clear repairs, prerequisite command order, no-ops, same-head races, pre-publication failures, nested alias isolation/capture and the real E01 flow. Every negative case compares complete public observations of current states and all known history, absent proposed next revisions and unrelated populated Maps; pure overflow fixtures additionally remain unchanged.

`tests/types/public-contract.ts` verifies SettleCommand/outcome narrowing, distinct ID brands, absence of caller introduction metadata and opaque prepared construction, required reopen reason, unavailable arbitrary result installation, plain-record resulting facts and no extra public validation/import/fault port.

Reopen is a Ticket lifecycle operation, not whole-Map rollback. Rollback, Ticket/Map deletion, sharing, rendering, authentication, PostgreSQL, transport and plugin packaging remain outside M1. Planning/archive content and accepted terminology are unchanged.
